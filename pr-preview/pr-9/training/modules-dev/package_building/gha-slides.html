So far, we have been running various checks (e.g. R CMD check) locally. This has two main drawbacks.

First, we may simply forget to run these checks, in which case we might discover bugs a long time after introducing them, making the debugging process more painful.

Second, our check results only apply to our development environment. We might run these checks in a new R session, but our results may depend on our R version, on other dependencies in our system, or on our operating system!

An essential tool in software development is continuous integration, often referred to as “CI”. The objective of CI is to run a battery of automated checks on every change in the repository, whether it be when we push a new commit to the main branch or when someone opens a pull request. In this section, we are going to explore some CI tools and workflows dedicated to R package development. Since GitHub is the most popular code hosting platform, we are going to focus on their own CI services, Github Actions, but the content of this section can be transposed to other platforms.

GitHub Actions

GitHub Actions (sometimes abbreviated to “GHA”) is a service provided by GitHub to run CI workflows. We will demonstrate how to use it by adding a workflow to run R CMD check on every commit to main, on every commit to a PR, and on multiple operating systems and R versions.

Keep in mind that a CI workflow is not limited to checking R packages. It is essentially a list of steps where each step can run some code. Therefore, you can create workflows to check spelling in your repository, to run code stylers and linters, to check that all URLs are valid, and many other things.

A basic workflow for R CMD check

We will start by creating a new basic workflow for R CMD check. This will run on a single OS and only when we push a change to main. In practice, we rarely create workflows for R package development from scratch. Instead, we use a collection of workflows maintained on another GitHub repository: r-lib/actions. In particular, the examples folder contains many examples of useful workflows.

We will start by adapting the workflow named check-release.yml. For clarity, we will rename this file R-CMD-check.yaml. All GHA workflows need to be stored in the .github/workflows folder. Hence, we end up with the following file:

.github/workflows/R-CMD-check.yaml
on:
  push:
    branches: [main]

name: R-CMD-check

permissions: read-all

jobs:
  R-CMD-check:
    runs-on: ubuntu-latest
    env:
      GITHUB_PAT: ${{ secrets.GITHUB_TOKEN }}
      R_KEEP_PKG_SOURCE: yes
    steps:
      - uses: actions/checkout@v6

      - uses: r-lib/actions/setup-r@v2

      - uses: r-lib/actions/setup-r-dependencies@v2
        with:
          extra-packages: any::rcmdcheck
          needs: check

      - uses: r-lib/actions/check-r-package@v2
        with:
          upload-snapshots: true
          build_args: 'c("--no-manual","--compact-vignettes=gs+qpdf")'

There is a lot to unpack here! The on block tells GitHub when this workflow should be run. For now, we only want to run it when we push a new commit to main. We then have the name and permissions of the workflow. In some cases, we want to give some write access to workflows to make automated commits for instance, but here we can leave it as read-all.

The jobs part is where we define the steps that will be run by our workflow. Note that one workflow can run multiple jobs, but here we just have one named R-CMD-check. This will run on ubuntu-latest (the most popular Linux distribution). In most R-related workflows, we will find the next three steps: actions/checkout, r-lib/actions/setup-r, and r-lib/actions/setup-r-dependencies, that are here to install R and our package dependencies.

Once this is done, the last step is to run R CMD check via r-lib/actions/check-r-package.

Run this workflow in more cases

This is a good start but for now it only runs when we push changes to main. This is a bit too late, we would like to run this in a PR so that test failures due to changes in a PR do not affect the “clean” development version. We can tweak the on block to run this in pull requests as well:

.github/workflows/R-CMD-check.yaml
on:
  push:
    branches: [main]
  pull_request:

[ ... ]

Now, this workflow will run on every change in every pull request.

Expanding R versions and platforms

We now run this more frequently, which addresses the first drawback of running tests locally (the developer might forget to run them), but it doesn’t fix the second drawback (depending too much on the developer environment). Let’s now run this workflow on more platforms and with more R versions!

To avoid adding one jobs per configuration option, we can create a matrix with all our desired inputs:

.github/workflows/R-CMD-check.yaml
[ ... ]

jobs:
  R-CMD-check:
    runs-on: ${{ matrix.config.os }}
    name: ${{ matrix.config.os }} 

    strategy:
      fail-fast: false
      matrix:
        config:
          - {os: ubuntu-latest}
          - {os: macOS-latest}
          - {os: windows-latest}

[ ... ]

We have added a matrix of config options. For now, each config has a single key, os, that contains the operating system we want to use. We can retrieve this value with ${{ matrix.config.os }}, which we use both in runs-on (to actually change the OS used by the workflow) and in name (so that we can easily distinguish the output of these CI workflows).

We can add more keys to the config, such as an r key to define the R version we want to use.

.github/workflows/R-CMD-check.yaml
[ ... ]

jobs:
  R-CMD-check:
    runs-on: ${{ matrix.config.os }}
    name: ${{ matrix.config.os }} (${{ matrix.config.r }})

    strategy:
      fail-fast: false
      matrix:
        config:
          - {os: ubuntu-latest,  r: 'release'}
          - {os: macOS-latest,   r: 'release'}
          - {os: windows-latest, r: 'release'}
          - {os: windows-latest, r: 'oldrel-1'}

[ ... ]

      - uses: r-lib/actions/setup-r@v2
        with:
          r-version: ${{ matrix.config.r }}

[ ... ]

We added r: 'release' to use the latest stable version of R, and r: 'oldrel-1' to use the previous R version. We use this matrix.config.r key in two places: in the name (for the same reason as before), and in the setup-r step, where we actually install R.

We still have a single workflow, but it now runs four different jobs with various OS and R versions. Note that you could also add more ancient R versions.

Some changes for a better developer experience

We could stop here, but instead I would like to highlight two changes that improve the efficiency and robustness of CI workflows.

The first one is about timeout. GitHub Actions is a very useful tool, but it depends on many external factors, starting from the fact that if GitHub has some issues then GHA might be affected. On top of that, issues in R versions or R dependencies can lead to longer-than-usual workflows that sometimes run for hours! Using the timeout-minutes parameter is an easy way to avoid this problem.

.github/workflows/R-CMD-check.yaml
[ ... ]

jobs:
  R-CMD-check:
    runs-on: ${{ matrix.config.os }}
    timeout-minutes: 20

[ ... ]

Using a 20-minute timeout is in general more than enough to check a standard R package.

The second change is to use concurrency. When we work in a pull request, we may push several commits in a few minutes, and each of these commits triggers the workflows. The default behaviour is to queue workflows, which can significantly slow us down since we have to wait for workflows associated to early commits while we are only interested in the results for our last commit.

The concurrency parameter changes this by automatically cancelling workflows if a newer one is triggered:

.github/workflows/R-CMD-check.yaml
[ ... ]

name: R-CMD-check

concurrency:
  group: ${{ github.workflow }}-${{ github.head_ref }}
  cancel-in-progress: true

jobs:

[ ... ]

Final workflow

For reference, here is our final workflow:

.github/workflows/R-CMD-check.yaml
on:
  push:
    branches: [main]

name: R-CMD-check

concurrency:
  group: ${{ github.workflow }}-${{ github.head_ref }}
  cancel-in-progress: true

permissions: read-all

jobs:
  R-CMD-check:
    runs-on: ${{ matrix.config.os }}
    name: ${{ matrix.config.os }} (${{ matrix.config.r }})
    timeout-minutes: 20

    strategy:
      fail-fast: false
      matrix:
        config:
          - {os: ubuntu-latest,  r: 'release'}
          - {os: macOS-latest,   r: 'release'}
          - {os: windows-latest, r: 'release'}
          - {os: windows-latest, r: 'oldrel-1'}

    env:
      GITHUB_PAT: ${{ secrets.GITHUB_TOKEN }}
      R_KEEP_PKG_SOURCE: yes

    steps:
      - uses: actions/checkout@v6

      - uses: r-lib/actions/setup-r@v2
        with:
          r-version: ${{ matrix.config.r }}

      - uses: r-lib/actions/setup-r-dependencies@v2
        with:
          extra-packages: any::rcmdcheck
          needs: check

      - uses: r-lib/actions/check-r-package@v2
        with:
          upload-snapshots: true
          build_args: 'c("--no-manual","--compact-vignettes=gs+qpdf")'
