Duplicating code makes it easy to introduce bugs.

Let’s write a function instead of repeating this formula four times.

Writing a function

The most basic function


my_std <- function() {}


  • my_std is the function name
  • function() is the function definition, that can take function arguments
  • {} contains the function body

The most basic function


For now, this function is useless:

my_std()
NULL


Let’s add a simple message:

my_std <- function() {
  print("Hello from my_std()!")
}

my_std()
[1] "Hello from my_std()!"


Let’s add function parameters!

Introduce function parameters


Function parameters are inputs passed by the user.

They are the parts that the user can modify to change the output.


To move existing code into a function, we need to identify its “moving” components and its “stable” components.

Introduce function parameters


Parts in red are the parts that change across lines (the column name that is used):

iris[["Petal.Length"]] <- (iris[["Petal.Length"]] - 
  mean(iris[["Petal.Length"]])) / 
  sd(iris[["Petal.Length"]])
iris[["Sepal.Length_std"]] <- (iris[["Sepal.Length"]] - 
  mean(iris[["Sepal.Length"]])) / 
  sd(iris[["Sepal.Length"]])
iris[["Petal.Width_std"]] <- (iris[["Petal.Width"]] - 
  mean(iris[["Petal.Width"]])) / 
  sd(iris[["Petal.Width"]])
iris[["Sepal.Width_std"]] <- (iris[["Sepal.Width"]] - 
  mean(iris[["Sepal.Width"]])) / 
  sd(iris[["Sepal.Width"]])

Introduce function parameters


Therefore we can create a column parameter to specify which column to use in the computation:


my_std <- function(column) {}

Add the function body


The function body takes the code that doesn’t change across lines:

my_std <- function(column) {
  (iris[["Petal.Length"]] - 
    mean(iris[["Petal.Length"]], na.rm = TRUE)) /
    sd(iris[["Petal.Length"]], na.rm = TRUE)
}

and we can replace the moving parts by our new column parameter:

my_std <- function(column) {
  (iris[[column]] - mean(iris[[column]], na.rm = TRUE)) /
    sd(iris[[column]], na.rm = TRUE)
}

Note

We don’t assign the output inside the function: the function merely makes the computation and we assign its output to our object when we call the function.

Use our new function



iris[["Petal.Length_std"]] <- my_std("Petal.Length")
iris[["Sepal.Length_std"]] <- my_std("Sepal.Length")
iris[["Petal.Width_std"]] <- my_std("Petal.Width")
iris[["Sepal.Width_std"]] <- my_std("Sepal.Width")

Notice how it is much easier to check whether we made a typo in this code.

Validate function parameters


We can pass our own values to my_std(), so we can also make mistakes!

If we pass a column name that doesn’t exist in the data:

my_std("unknown_column")
Warning in mean.default(iris[[column]], na.rm = TRUE): argument is not numeric
or logical: returning NA
numeric(0)

This doesn’t error, it just throws a warning and returns a useless result!

  we need to check user inputs

Validate function parameters


Step 1: list all input requirements.

  • the column should be a single value, e.g. my_std(c("Sepal.Length", "Petal.Width")) should fail;
  • the column should be a character value, e.g. my_std(1) should fail;
  • the column should exist in the data, e.g. my_std("column_1") should fail.

Validate function parameters


Step 2: check each of those.

my_std <- function(column) {
  if (length(column) != 1) {
    stop("The `column` parameter must be of length 1.")
  }
  if (!is.character(column)) {
    stop("The `column` parameter must be a character.")
  }
  if (!(column %in% names(iris))) {
    stop("Column '", column, "' doesn't exist in the data.")
  }

  (iris[[column]] - mean(iris[[column]], na.rm = TRUE)) / sd(iris[[column]], na.rm = TRUE)
}

Set default value for parameters


Instead of setting na.rm = TRUE in the function body, we could let the user determine this option.

We can add a na.rm parameter and use its value in mean() and sd():

my_std <- function(column, na.rm) {
  # [parameter checks]

  (iris[[column]] - mean(iris[[column]], na.rm = na.rm)) / sd(iris[[column]], na.rm = na.rm)
}


For conciseness, I hid the parameter checks we wrote before.

Set default value for parameters


This works but forces the user to write na.rm = TRUE (or FALSE):

head(my_std("Sepal.Length", na.rm = FALSE))
[1] -0.8976739 -1.1392005 -1.3807271 -1.5014904 -1.0184372 -0.5353840

We could set a default value instead (like in mean() for instance):

my_std <- function(column, na.rm = FALSE) {
  # [parameter checks]

  (iris[[column]] - mean(iris[[column]], na.rm = na.rm)) / sd(iris[[column]], na.rm = na.rm)
}

Exit a function early


Sometimes, we want to return an object early on instead of executing the rest of the function.

We can use return() for this.

Example: return NA if the input contains at least one NA value:

f <- function(x) {

  if (anyNA(x)) {
    return(NA)
  }

  # if x doesn't contain NA, then we continue the function here...
}

Other ways to use and create functions

Functions as arguments


Functions are just another type of objects: they can be updated by the user, assigned to variables, and passed over to other functions:

my_variable <- mean


The absence of parentheses after mean means we are not evaluating the function, just refering to it.

Functions as arguments


The family of apply functions can use these function objects:

data_list <- list(a = rnorm(100), b = rnorm(100, mean = 3))
lapply(X = data_list, FUN = median)
$a
[1] -0.147277

$b
[1] 3.095837

Anonymous functions


So far, we have seen and used named functions.

Generally, it is good practice to give your variables and functions informative names.


But sometimes you just need a quick, short throwaway function that serves one purpose.

For this, you can use anonymous functions. These are defined on the spot and immediately evaluated without being assigned to a variable.

Anonymous functions


Once again, these can be very useful in *apply() functions (and in other places):

data_list <- list("a" = rnorm(100), "b" = rnorm(100, mean = 3))
lapply(X = data_list, FUN = function(x) abs(x[3] - x[5]))
$a
[1] 0.1897032

$b
[1] 0.9237218
