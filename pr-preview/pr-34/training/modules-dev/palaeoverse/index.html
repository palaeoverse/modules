Getting started with palaeoverse

An introduction to the palaeoverse R package

This is a ~2 hour module introducing palaeoverse, a community-built R package that provides shared, reproducible tools for preparing and analysing palaeontological data. You will learn the philosophy behind the package, explore its core functionality, and work through a hands-on examples that takes fossil occurrence data from raw records to a finished plot.

1 Introduction

Computational tools are now at the heart of modern palaeontology. From cleaning datasets to running complex analyses, software underpins much of what we do.

palaeoverse is an R package developed by palaeobiologists, for palaeobiologists. Its aim is to provide a community-driven toolkit of generic functions that address the tasks palaeobiological researchers run into again and again, from preparing and cleaning occurrence data to binning records in time and space and summarising the results. Rather than reinventing these steps for every project, palaeoverse allows you to draw on well-documented, tested functions that the community has built and refined together.

The package deliberately does not implement statistical analyses. Instead, it provides auxiliary functions that streamline the workflow around those analyses, helping you get your data into the right shape and keep your code clear. This design means palaeoverse slots neatly alongside the methods you already use, while improving the readability, transparency and reproducibility of your code. The package is open and collaborative, so researchers at any career stage are welcome to suggest new functions, report issues and contribute to its development.

1.1 Learning objectives

By the end of this module, you will be able to:

  • Install and load palaeoverse, and locate its documentation, vignettes and help resources
  • Describe the philosophy and design principles behind palaeoverse, and the kinds of problems it is designed to solve
  • Identify the main groups of functions available in palaeoverse and match them to common stages of a palaeontological workflow
  • Apply palaeoverse functions to explore, prepare and visualise a fossil occurrence dataset
  • Implement palaeoverse into your own research workflows

1.2 Who is this module for?

You should be comfortable with basic R (data frames, functions, installing packages). Experience with fossil occurrence data, for example from the Paleobiology Database (PBDB), is helpful but not required.

1.3 Why use palaeoverse

Palaeobiological analyses rarely go straight from raw data to results. Before you can run a single model, you usually need to check taxonomic names, assign occurrences to time bins, work out where your fossils sat on the ancient Earth, and summarise sampling. These steps are essential, but they are also repetitive, error-prone, and often rewritten from scratch for every project. The palaeoverse R package exists to change that.

  • Save time on routine tasks. Functions for common tasks such as checking taxonomy (tax_check()), binning occurrences in time (bin_time()) and reconstructing palaeocoordinates (palaeorotate()) replace long, bespoke scripts with a few clear lines of code.
  • Write clearer, more readable code. Consistent function names, arguments and outputs make your scripts easier to follow, whether you are returning to them in six months or sharing them with a collaborator.
  • Make your research reproducible. Documented, version-controlled, and tested functions mean that others can follow exactly what you did, and rerun it, without deciphering a one-off workflow.
  • Keep full control of your analyses. palaeoverse does not impose a statistical framework. It prepares and supports your data, so it works alongside the methods and packages you already use.
  • Build on community expertise. The package is shaped and peer-reviewed by palaeobiologists working across taxa, time periods and questions, so its functions reflect real research needs rather than abstract design.
  • Join an open, welcoming project. Anyone can suggest a function, report a bug or contribute code, and the more people use and shape the package, the more useful it becomes.

2 Philosphy, Design Principles and Applications

2.1 Motivation

First released in 2022, palaeoverse was born from a frustration that will feel familiar to many researchers. Across the palaeontological community, many of us were independently writing similar code to clean, standardise and prepare data for analysis. Without shared tools or common workflows, this meant duplicated effort and results that were not always easy for others to reproduce.

Rather than continuing to work in parallel, a group of early-career researchers came together to tackle the problem collaboratively. The result was the palaeoverse R package.

2.2 Design

palaeoverse is built around a small set of principles that shape how the functions look and behave.

  • Built around occurrence data. Most functions expect an occurrence data.frame as input. Fossil occurrence data are records of the presence of a particular taxon at a unique location in space and time.
  • Modular. Each function does one job well, such as checking taxonomic names, binning ages, or estimating palaeocoordinates. You can use a single function in isolation or chain several together into a full workflow.
  • Flexible. Functions are not tied to a single data source. Column names are generally arguments rather than fixed requirements, so you can use data from the Paleobiology Database (PBDB), your own compilations, or other sources.
  • Transparent and reproducible. Functions are scripted, documented and open source, so every step of data preparation can be inspected, shared and repeated.
  • Well documented. Every function has a help page with worked examples, and vignettes demonstrate complete workflows.
  • Community-driven. Palaeoverse is developed openly, with input from researchers across career stages. Users are encouraged to suggest features, report bugs and contribute.
  • Peer-reviewed. Every function undergoes several rounds of review and testing by the development team before it is added to the package, which helps ensure the code is reliable, readable and consistent.
NoteAnatomy of an occurrence dataset

Occurrence data typically include columns describing:

  • Taxonomy, such as accepted name, genus and family
  • Time, such as maximum and minimum ages or named intervals
  • Space, such as longitude and latitude
  • Additional context, such as formation, collection or reference

Each row is a single record of something present at a particular place and time. That “something” is usually a taxon, but it does not have to be. In the reefs dataset, for example, each row is a fossil reef rather than a species. Most palaeoverse functions rely mainly on the time and space columns, so they work on either kind of record. Functions that deal with taxonomy, such as tax_unique(), additionally need the relevant taxonomic columns.

2.3 Applications

palaeoverse supports the early, and sometimes most time-consuming, step of palaeontological analyses. Typical applications include:

  • Cleaning and standardising occurrence data, for example by checking taxonomic names and removing duplicates
  • Binning occurrences into temporal and spatial units for analyses of diversity, turnover, and biogeography
  • Reconstructing palaeogeography by estimating where fossil localities were located in the past
  • Summarising taxa, such as estimating temporal and geographic ranges
  • Building reproducible workflows that can be shared alongside publications

These steps feed into a wide range of downstream analyses, including diversity dynamics, macroevolution, macroecology and biogeography. palaeoverse does not replace specialist analytical packages. Instead, it provides the shared groundwork that prepares data for them.

NoteWhere does palaeoverse fit?

Think of palaeoverse as the bridge between raw occurrence data and the analytical methods you want to apply.

3 How to use palaeoverse

3.1 Installation

The palaeoverse package can be installed from CRAN (recommended) or its dedicated GitHub repository if the development version is preferred. To install via CRAN, simply use:

install.packages("palaeoverse")

To install the development version, first install the remotes package, and then use install_github() to install palaeoverse directly from GitHub:

install.packages("remotes")
remotes::install_github("palaeoverse/palaeoverse")

Now you are able to load palaeoverse:

library(palaeoverse)

3.2 Getting help

Everyone gets stuck, and knowing where to look is one of the most useful skills you can develop. As with most packages, palaeoverse has several layers of support, from built-in documentation to wider community support.

3.2.1 Within R

Every function has a help page describing its arguments, outputs and examples. Open it with ?:

?tax_unique

To search for functions by keyword, use help.search() or its shorthand ??:

??latitude

To list all functions available in the package:

help(package = "palaeoverse")

Palaeoverse also includes vignettes, which are longer tutorials that walk through complete workflows:

# List all available vignettes
browseVignettes("palaeoverse")

3.2.2 Online

  • Package website: The palaeoverse website hosts the full function reference, vignettes and news on new releases. It is searchable and easier to browse than the help pages in R.
  • GitHub: The package source code lives in the Palaeoverse/palaeoverse GitHub repository. Check the existing issues first, as someone may already have asked your question.

3.2.3 Asking a good question

If you can’t find an answer, you can open an issue on GitHub. A clear report makes it far more likely you will get a quick and useful reply. Include:

  1. What you were trying to do, in a sentence or two
  2. A minimal reproducible example, using one of the built-in datasets where possible
  3. The error message or unexpected output, copied in full
  4. Your session information, which you can generate with:
sessionInfo()
Tip

The reprex R package is helpful tool when preparing a reproducible example.

NoteCiting palaeoverse

A quick note on behalf of the developers. If you use palaeoverse in your research, please cite the associated publication. Citations are one of the main ways our work is acknowledged, and they help keep the package maintained and improved (read more on this topic). You can access the appropriate citation via:

citation("palaeoverse")
