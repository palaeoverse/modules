Learning objectives

By the end of this module, you will be able to:

  • Install and load the palaeoverse package and access its example datasets
  • Explore and visualise the structure of a fossil occurrence dataset, summarising its taxonomic, temporal, and spatial coverage with simple tables and plots
  • Identify and resolve common data quality issues in occurrence records
  • Bin fossil occurrence data into temporal and spatial bins
  • Reconstruct palaeogeographic coordinates for fossil occurrences
  • Calculate and plot taxonomic richness through time from binned occurrences

1 Introduction

Computational tools are now at the heart of modern palaeontology. From cleaning datasets to running complex analyses, software underpins much of what we do.

1.1 Motivation

First released in 2022, palaeoverse was born from a frustration that will feel familiar to many researchers: across the palaeontological community, many of us were independently writing similar code to clean, standardise, and prepare palaeontological data for analyses. Without shared tools or common workflows, this meant a lot of duplicated effort and results that were not always easy for others to reproduce.

Rather than continuing to work in parallel, a group of early-career researchers came together in 2022 to tackle the problem collaboratively. The result was the zpalaeoverse` R package.

1.2 The palaeoverse package

palaeoverse is an R package developed by palaeobiologists, for palaeobiologists. Its aim is to provide a community-driven toolkit of generic functions that address the tasks palaeobiological researchers run into again and again, from preparing and cleaning occurrence data to binning records in time and space and summarising the results. Rather than reinventing these steps for every project, palaeoverse allows you to draw on well-documented, tested functions that the community has built and refined together.

The package deliberately does not implement statistical analyses. Instead, it provides auxiliary functions that streamline the workflow around those analyses, helping you get your data into the right shape and keep your code clear. This design means palaeoverse slots neatly alongside the methods you already use, while improving the readability, transparency and reproducibility of your code. The package is open and collaborative, so researchers at any career stage are welcome to suggest new functions, report issues and contribute to its development.

1.3 Why use palaeoverse

Palaeobiological analyses rarely go straight from raw data to results. Before you can run a single model, you usually need to check taxonomic names, assign occurrences to time bins, work out where your fossils sat on the ancient Earth, and summarise sampling. These steps are essential, but they are also repetitive, error-prone, and often rewritten from scratch for every project. The palaeoverse R package exists to change that.

  • Save time on routine tasks. Functions for common tasks such as checking taxonomy (tax_check()), binning occurrences in time (bin_time()) and reconstructing palaeocoordinates (palaeorotate()) replace long, bespoke scripts with a few clear lines of code.
  • Write clearer, more readable code. Consistent function names, arguments and outputs make your scripts easier to follow, whether you are returning to them in six months or sharing them with a collaborator.
  • Make your research reproducible. Documented, version-controlled, and tested functions mean that others can follow exactly what you did, and rerun it, without deciphering a one-off workflow.
  • Keep full control of your analyses. palaeoverse does not impose a statistical framework. It prepares and supports your data, so it works alongside the methods and packages you already use.
  • Build on community expertise. The package is shaped and peer-reviewed by palaeobiologists working across taxa, time periods and questions, so its functions reflect real research needs rather than abstract design.
  • Join an open, welcoming project. Anyone can suggest a function, report a bug or contribute code, and the more people use and shape the package, the more useful it becomes.

3 How to use palaeoverse

3.1 Installation

The palaeoverse package can be installed from CRAN (recommended) or its dedicated GitHub repository if the development version is preferred. To install via CRAN, simply use:

install.packages("palaeoverse")

To install the development version, first install the remotes package, and then use install_github() to install palaeoverse directly from GitHub.

install.packages("remotes")
remotes::install_github("palaeoverse/palaeoverse")

3.2 Documentation

As with all R packages, you can access function documentation through using help() or ?, for example:

# Get documentation for specific function
help(bin_time)
# or
?bin_time
# List of all functions
help(package = "palaeoverse")
Tip

You can also see all function documentation via the package’s dedicated website reference guide.

3.3 Citing palaeoverse

Before we get to the good stuff, a quick note on behalf of all developers. Behind every open-source package is a group of people who build, maintain, and support it, often in their own time and often without much recognition. If you use palaeoverse in your research, please cite the associated publication. Citations are one of the main ways this kind of work is acknowledged, and they help us keep maintaining and improving the package so that you can keep doing your research (read more on this topic). You can access the appropriate citation via:

citation("palaeoverse")

4 Design Principles and Applications

Functions in palaeoverse are designed around the assumption that most users’ data are stored in an occurrence data.frame. As such, this is the expected input data format for most functions. Fossil occurrence data comprise records of the presence of a particular taxon at a unique location in space and geological time.
